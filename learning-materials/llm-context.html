大模型的上下文（Context）

模型在一次推理里"看到的全部输入"——系统提示、对话历史、工具定义、检索结果，都在这里。

TL;DR

  • 上下文 = 一次调用里喂给模型的全部内容。
  • 它的长度上限叫"上下文窗口"，按 token 计量。
  • 上下文工程的本质，是把对的内容放在对的位置。

为什么这件事重要

模型看不到它"上下文"以外的东西。模型表现得聪明还是糊涂，几乎不取决于"它有多强"，而取决于"你喂它的上下文有多少、有多准"。上下文工程（context engineering）正在取代 prompt engineering，成为 2025 年之后 AI 应用开发者的核心技能。

2 · 解剖：上下文里到底装了什么

  • System prompt：给模型的"人设 / 规则 / 输出格式"，通常固定。
  • 对话历史：用户问过的、模型答过的，按时间顺序排列。
  • 工具定义：让模型知道有哪些工具可用、各需要什么参数。
  • 工具结果：之前工具调用的真实返回值，会被回填进上下文。
  • 检索结果（RAG）：从外部知识库挑出来的相关片段，往往是当前任务最关键的信息。
  • Few-shot 示例：放在上下文里的"示范问答"，用来引导风格或格式。
  • 缓存标识：API 层面用来告诉服务端"前面的内容没变，请复用缓存"。

3 · 运作机制

  1. 采集：把这一次对话所需的全部信息收集起来——记忆、检索、工具结果都算。
  2. 排序：把"最相关 / 最新 / 最要紧"的内容放上下文靠前的位置（首因效应让模型更"听"开头）。
  3. 压缩：超长时用摘要、删除、引用替代等方式瘦身；不重要的早期对话可丢弃。
  4. 校验：交付前确认上下文没拼错（比如角色标签、JSON 结构）。
  5. 输入模型：一次性喂入。模型只看见这"一张卷子"，看不见其他。

研究界有一句流行说法："Garbage in, garbage out" 在大模型时代有一个更具体的版本："你喂什么，模型就答什么"。

常见误区

  • "上下文越长越好"。不一定。研究普遍发现"Lost in the Middle"（中间内容最易被忽略）：写得长 ≠ 用得着。
  • "上下文 = 记忆"。错。上下文是一次性的输入；记忆是跨多次会话持久化的状态。
  • "上下文窗口 128k 就够用"。实际上，模型的"有效"上下文往往只有声称值的 60%–80%，超出后质量明显下降。
  • "调好 prompt 就万事大吉"。单靠 prompt 修修补补很快撞墙；上下文工程是把"送进模型前的那一段工程"当成独立学科来做。

5 · 代码级一瞥（构造一次最小请求的上下文）

messages = [
    {"role": "system", "content": "你是助教，回答要简洁。"},
    {"role": "user",   "content": user_question},
]

# 可选：检索后把检索到的资料插在用户问题之前
if retrieved:
    messages.insert(1, {
        "role": "system",
        "content": "以下是与问题相关的资料：\n" + "\n".join(retrieved)
    })

# 可选：把历史对话追加到末尾
messages += session_history

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=messages,        # <-- 这就是"上下文"
    temperature=0.2,
)

注意：这里没有"魔法"。模型好不好，几乎完全取决于 messages 这个列表里装的是什么、装得对不对。

6 · Recap & 自检

1. 大模型能"看见"没放进上下文的内容吗？不能。一次推理只有"上下文"这一份输入；其它都看不见。
2. 上下文窗口 128k 是不是表示能稳定用满 128k？不是。实际表现往往在声称值的 60%–80%，更长的部分会出现明显遗忘、答错、答非所问。
3. RAG 和"长上下文"哪种更好？各有所长。RAG 适合"精确查找某条事实"；长上下文适合"整段文本需要被理解"。一般经验：能用 RAG 就别把整个知识库塞进上下文，又贵又慢。
4. 上下文和记忆的区别是什么？上下文 = 这一次调用的全部输入；记忆 = 跨会话持久化的状态，检索后会注入上下文。两者协作，不要混为一谈。
5. "Lost in the Middle" 是什么意思？研究发现大模型对上下文开头和结尾的信息利用最好，中间段最易被忽略。所以"关键内容放首尾"是常用技巧。
6. 为什么说"上下文工程"比"调 prompt"更重要？因为 prompt 只是上下文的一小部分；上下文工程是对整个输入序列的位置、内容、长度、结构的系统化设计，影响更根本。
