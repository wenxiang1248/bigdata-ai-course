Agent（智能体）

一个能自己定计划、用工具、读结果、直到把目标做完的 AI 程序。

类比
一个能开火、看菜谱、顺手把厨房收拾了的厨师
本质
LLM + 工具 + 循环
关键能力
规划 / 调用工具 / 观察结果
最易混淆
≠ 单纯的聊天模型

TL;DR

  • Agent 是「会动手」的 AI，不是「会说话」的 AI。
  • 它由 大脑（LLM） + 工具 + 循环 组成。
  • Agent 的本质是 观察 → 思考 → 行动 的反复执行。

为什么这件事重要

单单一个聊天模型只能"在脑子里想"——它出不了你的对话框。Agent 让语言模型第一次能"碰"真实世界：发邮件、写文件、调 API、跑代码。一句话理解 Agent 是当下所有 AI 应用工程的入口。

2 · 解剖

一个完整的 Agent 通常包含以下部件。它们不一定全都出现，但缺了哪一个都会出问题：

  • 大脑（LLM / Policy）：负责读懂任务、拆解任务、决定下一步。
  • 工具（Tools）：让 Agent 能"做"事的能力，比如读文件、查数据库、调搜索、发邮件。
  • 记忆（Memory）：短期记忆是当前任务上下文，长期记忆是跨任务沉淀的事实。
  • 规划（Planner）：把大目标拆成可执行的小步骤，可能写成有向无环图（DAG）。
  • 反思 / 校验（Reflection）：执行后回头检查，发现问题再补救——这是从"能跑"到"能跑对"的关键。
  • 停止条件（Stop condition）：什么时候算"做完了"？是 Agent 最容易被忽视也最值钱的部分。

3 · 运作机制（一步步看）

  1. 接收目标：用户给一句话或一个任务说明。
  2. 规划：LLM 把目标拆成步骤，可写进待办列表。
  3. 选工具：每一步选一个最合适的工具，并填好参数。
  4. 执行：Agent 真的去"做"——读文件、调 API、跑命令。
  5. 观察结果：把工具返回的结果塞回上下文。
  6. 判断是否结束：是 → 整理输出；否 → 回到第 3 步。

4 · 对比与误区

普通 LLM 对话Agent
输出形式一段文字调用工具 + 文字结果
能否读你电脑文件不能能（通过工具）
能否执行多步单轮多轮循环，自动推进
出错怎么办你来纠错它自己反思再试
适用场景问答 / 写文案真实任务自动化

常见误区

  • "Agent = 更聪明的聊天"。错。Agent 的根本差别在于"能不能做"——不是"说得更好"。
  • "越复杂的 Agent 越好"。不一定。多工具的 Agent 不一定比单工具的 Agent 表现好，反而更容易跑偏。
  • "Agent 能 100% 自主完成所有任务"。现阶段绝大多数 Agent 仍然需要人在环（human-in-the-loop）确认关键步骤。
  • "Agent 不会幻觉"。错。它的语言模型部分依然会幻觉——所以工具失败、上下文拼错这类错误非常常见。

5 · 代码级一瞥（最小可运行的 ReAct 风格循环）

tools = {
    "search":  search_api,
    "python":  run_python,
    "file":    read_file,
}

history = [{"role": "user", "content": "上周的销售数据是多少？"}]

while not done(history):
    thought, action = llm_decide(history, tools)   # 思考 + 选工具
    if action is None: break
    name, args = action
    observation = tools[name](**args)               # 真去执行
    history += [
        {"role": "assistant", "content": thought},
        {"role": "tool", "name": name, "content": observation},
    ]

print(history[-1]["content"])

三件事：llm_decide 决定下一步；tools[name](**args) 真的去做；history 把一切装回上下文，让下一次决策看得见上一次的结果。

6 · Recap & 自检

1. Agent 和 LLM 的本质区别是什么？LLM 只能"想"并产出文字；Agent 能"做"——通过工具影响外部世界，并基于反馈循环推进任务。
2. 一个 Agent 最少需要哪三样东西？一个能决策的 LLM、一组可调用的工具、一个循环（让 Agent 能反复"观察 → 思考 → 行动"）。
3. 为什么要给 Agent 明确的"停止条件"？没有停止条件，Agent 会无限循环、烧光 token，甚至把事情做歪。停止条件 = 让 Agent 知道什么时候算"做完"。
4. Agent 失败的第一大原因是什么？工具失败 + 上下文污染：工具返回错的结果没被识别，或者历史上下文太长让 LLM 抓不到重点。
5. 为什么"反思"环节是从能用走向好用的关键？因为工具输出常常有歧义或错误，没有反思 Agent 会一错到底；有了反思，它能识别错误、改正路径。
6. 举一个生活化的 Agent 例子。你叫外卖：接收订单 → 拆解（取餐、配送、送达）→ 选交通工具 → 跑单 → 看反馈（路上堵不堵）→ 决定继续送还是改路线。这就是 Agent。
