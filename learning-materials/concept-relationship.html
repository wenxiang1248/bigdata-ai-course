Agent × Context × Skill

三个角色的关系：Agent 是干活的厨师，Skill 是操作手册，Context 是厨房台面上一摊开的所有东西。

Agent
动手执行的循环

每一次推理的全部输入
Skill

关系口诀
Skill 装进 Context，Context 喂给 Agent

TL;DR

  • Skill 是"该怎么做的指令包"。
  • Context 是"这一次所有的输入"——里头装着 Skill。
  • Agent 是"读 Context、按 Skill 干活"的执行者。

为什么这件事重要

分别学 Agent、Context、Skill 都很清楚，可一旦把它们放一起问"它们怎么协作"就懵了。这张图就是给 AI 应用工程师看的"全家福"——只要说清楚一次"用户来一句话，Agent、Context、Skill 三者怎么接力"，整个现代 AI 应用的骨架就立住了。

1 · 心智模型：三个角色，三层关系

2 · 解剖：一次完整任务的接力

  1. 用户发言。它本身会成为 Context 的一部分（作为 user 消息）。
  2. 挑 Skill。Agent 看自己的所有 Skill 的 description，挑一个最匹配的；找不到合适的就用通用 Agent 跑。
  3. 装填 Context。把 Skill 内容、记忆、检索结果、工具定义、当前消息按一定顺序拼好。
  4. 喂给 Agent。Agent 拿着这张"卷子"让 LLM 推理；LLM 决定要不要再调工具。
  5. 工具结果回填 Context。观察结果拼进 Context；某些 Skill 会要求"按 checklist 自检"。
  6. 判断是否结束。是 → 输出给用户；否 → 回到第 4 步。

4 · 对比与误区

维度AgentContextSkill
本质执行者输入材料操作手册
形式运行中的程序一组消息列表一个 Markdown 文件
生命周期会话期间持续运行每次调用都重新组装写一次长期存在
被谁"使用"使用 Context被 Agent 使用被 Agent 装进 Context
会改变吗执行中状态变化每次推理都不同作者更新才改变

常见误区

  • "Skill 是 Agent 的子集"。更准确地说：Skill 是 Agent 上下文的一部分；Agent 装不装 Skill 都能跑，只是稳定度不同。
  • "Context 越多越好"。Skill 一旦塞太多，会稀释 LLM 对当前任务的注意力。Skill 应该写得精简。
  • "Agent 跑得好主要靠模型"。更多情况下，它靠的是 Skill 的流程设计和 Context 的精准构造。

# 1) 匹配 Skill（由 Agent 触发）
skill = pick_skill(user_request, all_skills)
skill_md = skill.read_text()

# 2) 装配 Context
messages = [
    {"role": "system", "content": base_system_prompt},
    {"role": "system", "content": skill_md},                  # <-- Skill 进 Context
] + session_history + [
    {"role": "user", "content": user_request},
]

# 3) 喂给 Agent（LLM + 循环 + 工具）
while not done:
    reply = llm.chat(messages, tools=tool_specs)
    if reply.tool_call:
        result = run_tool(reply.tool_call)                    # 工具结果回填
        messages.append(tool_result_msg(result))
    else:
        messages.append(reply)
        break

# 4) 输出最终答复
print(messages[-1]["content"])

6 · Recap & 自检

1. 用一句话说出三者的关系。Skill 是静态指令包，被按需装进 Context，喂给 Agent 让它按这套流程干活；Agent 行动后产生的新工具结果又会回填 Context——三者构成一个闭环。
2. Skill 必须出现在 Context 里吗？被匹配到时是必须的。但"未必每次都加载"——Agent 只在判定它相关时把 Skill 的内容注入上下文。
3. 如果没有 Skill，Agent 还能跑吗？可以。Skill 是稳定器，不是引擎；任何 Agent 即便没有 Skill 也能循环、调用工具——只是稳定性差。
4. 为什么说 Skill 不该写得太长？因为 Skill 进 Context 会占 token；过长的 Skill 会让 LLM 抓不到重点，效果反而变差。
5. 哪些东西属于 Context，哪些不属于？属于：system prompt / user & assistant 历史 / 工具定义 / 工具返回值 / 检索片段 / Skill 当前注入的部分。不属于：长期记忆（仅当被检索后注入时算）、训练数据、模型之外的任何状态。
6. 给我一个三层都用上的具体例子。用户在 WorkBuddy 里说"帮我提交今天的大作业代码"。Agent 看到一个叫 assignment-submit 的 Skill 被命中；把 Skill 内容注入 Context；结合当前 git 状态、commit message 历史；调用 git 工具，工具结果回填；最后输出提交报告。
