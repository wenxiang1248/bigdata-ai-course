Skill（技能）

一份"教 AI 怎么完成一类任务"的可复用说明——把零散经验沉淀成一个可调用的工作流。

类比
一本你写的 SOP/操作手册
本质
把"经验 + 流程 + 风格"打包成一个入口
两个组件
when to use · how to do
核心价值
让同样的任务不再每次重写 prompt
典型误区
把 Skill 当万能 prompt 库

3 ·结构化解释

3.1 · 心智模型：写给下一任"我"的 SOP

把 Skill 想成"一份你自己写的、操作某类任务的标准作业流程"：

  • 开头一段触发条件——"什么时候我才需要翻开这本手册"。
  • 中间一段步骤与规则——按顺序，要做到什么程度。
  • 结尾一段自检 / 异常处理——做完后看一眼对不对、出错了怎么回退。

Skill 的"魔法"不在于它有多少权力，而在于它把那些"我每次都要重新说一遍"的经验固化下来。

3.2 · 组成解剖

把 Skill 拆到代码级别，它通常由这几段组成：

段落作用不写会怎样
frontmatter告诉系统"我是谁、什么时候该被匹配"系统不知道何时调用
when to use / not把"做什么、不做什么"边界划清被滥用，模型不知所措
Inputs列出可调用的字段（必填/可选）每次都得说一遍参数
Output contract约定产出长什么样（结构、长度、风格）每次产出风格漂移
Workflow一步步的固定动作每次随机排列
Quality checklist完成前自检80% 的常见错误漏掉

3.3 · 运作机制（按步骤展开）

  1. 匹配：用户输入进来，系统拿 frontmatter 的 description 和触发词匹配，决定要不要把这份 Skill 加载。
  2. 注入：匹配的 Skill 的正文会被注入 Agent 的上下文（典型形式是一段 system 增强）。
  3. 执行：Agent 按 Skill 中的 workflow 一步步做。
  4. 检查：走完 Quality checklist，决定通过 / 回退。
  5. 回写（可选）：把本次经验回写到 Skill，让它下一次更强。

3.4 · 为什么这件事重要

因为"反复写同样的 prompt"是 AI 时代最大的隐性成本。Skill 让你把一次性 prompt 升级成可复用资产——它能跨人、跨项目、跨会话复用，还能被你持续维护。WorkBuddy 这类 Agent 把 Skill 作为一等公民，正是因为它们决定了一个 Agent 在你的工作流里到底专不专业。

3.5 · 代码级一瞥（一个最小可用的 Skill）

# 文件：.workbuddy/skills/concept-learning-material/SKILL.md
---
name: concept-learning-material
description: Generate a structured, visually rich single-file HTML
  learning material for a given concept. Use when the user wants to
  deeply understand or teach a single concept. Triggers: "生成学习资料",
  "讲解 X", "concept learning material".
---

# Concept Learning Material Generator

## When to use
- User: "Make a learning page for X"
- User: "Teach me X"

## Inputs
- `concept` (required) — the concept to teach
- `style_hint` (optional) — e.g. "for first-year students"

## Workflow
1. Disambiguate the concept if its name has multiple meanings.
2. Write 3–5 learning goals with verbs in the head.
3. Write the structure section by section, anchored by an SVG.
4. Run the quality checklist before saving.

## Quality checklist
- [ ] Page opens without external requests.
- [ ] All 7 segments present and in order.
- [ ] No invented sources.

这一份 Skill 共 25 行——但只要它在 WorkBuddy 中被检测到，凡是说"讲解 RAG 一下"的用户消息，它就会自动激活。

4 ·应用案例：把每周写周报这件痛苦事沉淀为 Skill

场景：你是产品经理，每周五下午要写一份 800 字的周报——三大模块（本周进展、本周数据、风险 & 需要协同）。过去 8 周，你每次都重新写一段 prompt，效果忽高忽低。

第一步：把它当 Skill 写出来。

  • name: weekly-pm-report
  • when to use: "写本周周报 / 整理本周工作 / 帮我过一下 PM 周报的稿子"
  • inputs: raw_notes（散落的项目笔记） + goal_template（你常用的结构）
  • workflow:
    1. 按 KPI 视角把 raw_notes 重新分组；
    2. 每段给出"状态 + 数字 + 决策点"三件套；
    3. 把"风险"放最后一段并标红；
    4. 全文 600–900 字，过一次 SOP 里写的"客不客观检查"。
  • quality checklist: 数字有出处；不夸大；不要堆 emoji；不"赋能"。

第二步：把它放到项目级 Skill 目录下，并提交到 Git。

结果：从此你每周只需要把笔记贴进来，说一句"按 weekly-pm-report 跑一下"。Skill 负责把"上周的格式"重新长出来，不用你再想"这次又该从什么角度写"。这就是 Skill 的价值——把零散经验变成可复用流程。

5 ·概念辨析

5.1 · Skill vs Prompt vs Agent vs Tool

维度SkillPromptAgentTool
本质可复用的工作流文档一次性输入运行中的程序可被调用的函数
谁来写人/作者人人/Skill/Agent 共同开发者
是否跨会话是否取决于实现是
有副作用取决于 Skill 是否要求 Agent 调工具无通常有通常有
谁能调匹配触发词的 Agent模型用户/上层系统Agent

最简单的口诀：Prompt 是请求，Skill 是手册，Agent 是执行者，Tool 是硬件接口。

5.2 · 常见误区

  • "Skill = 万能 prompt 库" — 一个 Skill 做一件事；做太多件事它会糊。
  • "description 越短越好" — description 太短会让系统匹配不上，太长会让系统误匹配。
  • "Skill 可以写在对话里" — 对话里的提示词不是 Skill，因为它不会跨会话被自动加载。
  • "Skill 一次写好就完事" — 高价值 Skill 是会随使用进化的——常见失败模式应回写到 Quality checklist。
  • "用户级 Skill 和项目级 Skill 等价" — 前者随你走，后者随项目走；放进项目目录等于告诉团队"这一手是这个项目的共识"。

6 ·自测问题

Q1 · Skill 和 prompt 的根本区别是什么？ Prompt 是一次性输入，寿命 = 一次对话；Skill 是可复用工作流，寿命 = 跨会话、跨用户。被匹配到的 Skill 会被注入上下文，被当作 SOP 来执行；prompt 只是被消费一次。
Q2 · 一个最小可用的 Skill 需要哪些字段？ 至少四件：① name / description（frontmatter）；② when to use 触发条件；③ workflow 工作流步骤；④ quality checklist 完成前自检。
Q3 · 什么时候放在 ~/.workbuddy/skills/，什么时候放在仓库的 .workbuddy/skills/？ 用户级 (~/.workbuddy/skills/)：跨项目、与个人习惯强相关、与代码无关（如个人写作风格）；
项目级 (<repo>/.workbuddy/skills/)：与本项目业务强相关、应被团队成员共享。
Q4 · 为什么 Skill 应该尽量"专一"？ 描述越宽的 Skill，触发时越容易把无关任务拽进来；模型把"什么都做"的工作流塞进上下文后，输出的稳定性会下降。一个 Skill 一件事，几件事就用几个 Skill，是性价比最高的写法。
Q5 · Skill 既然写在文档里，那 Agent 是怎么"看见"它的？ 匹配阶段：系统拿用户消息和 Skill 的 description / 触发词做匹配；命中后把 Skill 正文注入 Agent 的上下文（系统提示增强或工具列表）。Skill 通过被读进上下文而生效。
Q6 · 一个 Skill 完成了第一次使用后，最值得做的"维护动作"是什么？ 把本次失败模式回写进 Quality checklist。这种"小本经营式"的迭代，比每季度大改一次更能让 Skill 越用越好。
